# The 8 November batch

Part of [the plan](../PLAN.md). Mike's list from using Point, 8 November 2026. Links and recall, from the same list, are in [Links and recall](links-and-recall.md).

## The Mac

**Search and the explorer**
- **Swap the key commands** for the search panel and the explorer. Done: ⌘E is now the two-column explorer, ⌘F the search palette; ⇧⌘E (Run Command) and ⇧⌘F are as they were. Shortcuts changed in Settings keep their own keys. The menu names now match: ⌘E is Explorer and ⌘F is Search Vault, in the menus, the palette and the shortcut list. (The shortcuts' saved IDs keep their old names, so changed shortcuts stay put.)
- **The explorer's left side matches the sidebar:** folders and the types turned on for the sidebar, and no tags if the sidebar hides them. Done: Types (those chosen for the sidebar) first, then Folders, then Tags only if the sidebar shows them.

**Lists**
- **A better way to make a list note.** Today it only seems possible from the explorer, which is odd and hard to find.

**The list's filters panel**
- **Squarer buttons**, the kind macOS uses in its own settings, in place of the capsules.
- **Cancel and Done a bit larger** than the Add button. Done, both: rounded-rectangle buttons, Cancel and OK large, Add condition regular size. Checked in the app, 9 November.

**The links panel at the bottom**
- Its layout is bad: stretch the content area wider. (The redesign is in [Links and recall](links-and-recall.md): content as wide as the note's, at most.)

**The clipper** (see [The clipper](clipper.md))
- **A clip opens a new window, not a new tab.** It must open in a tab of the window already open. Done: SwiftUI was opening a window for each `point://` link; now the clip opens in a tab of the window in use, whether Point was running or was started by the clip.
- **The icon in Dia looks tiny**, because it's the whole app icon. Use only the shapes inside it, without the background, with the centre shape larger. Done (Mike's new icons, 9 November).

**Editing**
- **The line joining a list's items** sometimes runs too far. It should stop where an empty line separates items. Done: an empty line just above the next item ends the line there.
- **Markdown mode in a split** applies to both notes; it should apply only to the one it was turned on in. Done: each side of a split has its own. The View menu and its shortcut change the side being worked on; each side's ••• menu changes that side. Not kept between launches, as before.
- **A word count:** some way to see the current note's. Done: View › Show Word Count (off to start with) shows it in the bottom corner the links leave free, on glass; "12 of 1,234 words" with a selection. The text only, not the properties.
- **1 or 2 px more space** between the breadcrumb and the note's title. Done: 7 → 9 pt.

**Templates and assets in the sidebar**
- The templates folder and the attachments (assets) folder shouldn't be in the folder tree. They go in the top area with the types and Bookmarks, as places of their own.
- Point finds both from the vault's settings (Obsidian's templates folder and attachment folder), so they're found wherever they are. Mike can move them (out of a meta folder, say) if that helps; to tell him if it's needed.
- A folder holding nothing but these two would be left empty in the tree; hide it too, or leave it.
- Done: both sit at the top of the sidebar, named Templates and Attachments with their own icons, and head the explorer's Folders. The tree leaves them out, and a folder holding nothing but them. Attachments only when Obsidian puts them all in one folder (not beside each note). No need to move them.

**Liquid Glass buttons and their menus**
- A menu from a glass button should open over the button, growing out of it with the system's animation, as in macOS's own apps. Point's menus open below and apart from the button, which doesn't feel like macOS. Check how each is made (a SwiftUI `Menu` in a glass button style, or a button that shows a menu itself) and use the system's own glass menu button where possible. Done for the two that had menus (each side's ••• and the sort button): on macOS 26 they're now the system's glass pull-down button, so macOS places and animates the menu. The animation not yet looked at (it can't be checked in the background).

**Tabs**
- **Hovering a tab** shouldn't show a pill shape. Show only the close (X) icon, and turn the tab's text black. Done: no shape behind on hover, and the title in the text colour. Hover not yet looked at in the app.

**Tabs, splits and the explorer** (needs thinking through)
- It's hard to tell which side of a split will change when you open a note.
- Maybe scope the open tabs to their side of the split.
- Maybe keep the explorer over the pane it will open into.

## The iPhone

- **Home:** no New folder button. Done (folders' own screens still have it).
- **Screens with a sort button:** move sorting into the ••• menu. Done: "Sort by" in the ••• menu, showing the current order; a list with no other actions gets the menu for sorting alone. Not yet looked at on a phone.
